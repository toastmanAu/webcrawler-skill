### Fiber PeerID Derivation (IMPORTANT — non-libp2p)
- Tentacle uses SHA256 multihash of RAW pubkey bytes (NOT protobuf-wrapped)
- Formula: bytes([0x12, 0x20]) + sha256(compressed_pubkey_bytes)
- Then base58-encode the result
- Do NOT wrap in protobuf before hashing — that gives wrong result

### Protocol details confirmed:
- SecIO framing: 4-byte big-endian length prefix (not LE!)
- Yamux: big-endian throughout
- Tentacle inner frame: 4-byte LE length (includes proto_id + flags bytes)
- SecIO uses P-256 for ephemeral ECDH (not secp256k1!)
- Static keys: secp256k1 (for identity); ephemeral: P-256 (for ECDH)
- CKB protocol IDs: identify=0, ping=1, discovery=2, light_client=100

### NerdMiner Debug — Root Cause Found
- nerd1 (192.168.68.86) power cycled, reconnected, showing 7–10 KH/s on screen
- Connected to proxy, authorized, receiving jobs — but **zero share submissions**
- Debug logging added to solo-proxy.js revealed: subscribe, authorize, suggest_difficulty — then silence
- **Root cause**: firmware `checkValid()` bug in `src/utils.cpp`
  - `memcpy(diff_target, &target, 32)` — `&target` passes address of the pointer (stack var), not the data
  - Should be `memcpy(diff_target, target, 32)`
  - Fix: hashes were being compared against random stack garbage → never submitted
- **Also found**: proxy was sending 5-param mining.notify (ViaBTC format) but firmware expects 4-param
  - Old: `[job_id, pow_hash, height, target, clean_jobs]`
  - Fixed: `[job_id, pow_hash, target, clean_jobs]`
- **Also fixed**: mining.submit param destructuring `[, jobId, , , nonce]` → `[, jobId, nonce]` (3-param)

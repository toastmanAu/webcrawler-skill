## Telegram Mini App — Best Practices & Learnings (2026-03-09)

### Caching — The Real Problem
- GitHub Pages serves with default caching headers; Telegram WebView respects them AND caches the app session separately
- `?v=N` URL param on the bot menu button helps but doesn't fully bust Telegram's session cache
- **Proper fix**: Cloudflare Pages — set `Cache-Control: no-store` on `index.html`, let hashed JS/CSS assets cache normally
- Vite content-hash filenames (`main-[hash].js`) are correct — every deploy gets new filenames
- `setChatMenuButton` without `chat_id` only sets the global default — must pass `chat_id` to override for a specific user

### Debugging Mini Apps on Device
- **Android**: Settings → scroll to bottom → long-press version number twice → Enable WebView Debug → connect to Chrome via `chrome://inspect/#devices`
- **iOS**: Requires Safari on macOS + enable Web Inspector in iOS Safari settings + connect via cable → Develop menu in Safari desktop
- **Eruda**: Lightweight floating in-app devtools — add `<script src="//cdn.jsdelivr.net/npm/eruda"></script><script>eruda.init()</script>` for debugging on devices without desktop Safari. Has reload button.
- **Telegram Desktop Beta**: Settings → Advanced → Experimental → Enable webview inspecting → right-click → Inspect

### Telegram WebApp API — Key Methods to Always Use
```js
tg.ready()                          // always call on boot
tg.expand()                         // full height
tg.enableClosingConfirmation()      // prevent accidental close
tg.disableVerticalSwipes()          // IMPORTANT: prevents close-on-swipe inside scrollable content
tg.requestFullscreen()              // fullscreen mode (Bot API 8.0+)
tg.addToHomeScreen()                // offer home screen shortcut
tg.checkHomeScreenStatus()          // check if shortcut exists
```

### Safe Area — Must Respect on iPhone
```js
// Bot API 8.0+ — use these to avoid overlapping notch/home bar
tg.safeAreaInset        // { top, bottom, left, right }
tg.contentSafeAreaInset // inner content safe area
// CSS approach:
// padding-bottom: env(safe-area-inset-bottom)
// on bottom nav to avoid home indicator overlap
```

### Storage — Prefer New APIs Over localStorage
```js
// Bot API 9.0 (April 2025) — persistent, survives reinstall
tg.DeviceStorage.setItem(key, value)
tg.DeviceStorage.getItem(key)
// SecureStorage — for sensitive data (private keys, tokens)
tg.SecureStorage.setItem(key, value)
```

### Performance — Adaptive for Low-End Devices
- Android User-Agent includes device performance class (low/medium/high)
- Parse `navigator.userAgent` for `TelegramWebApp` performance hints
- Reduce/disable particle animations on low-performance devices
- Use `tg.isActive` + `tg.isFullscreen` to adjust rendering

### Launching Methods (7 ways)
1. Bot menu button (what we use — `setChatMenuButton`)
2. Keyboard button (`web_app` type KeyboardButton)
3. Inline button (`web_app` type InlineKeyboardButton)
4. Direct link: `t.me/BotName/appname?startapp=param`
5. Inline mode (from `@bot` results)
6. Attachment menu (sidebar icon)
7. Main Mini App button on bot profile (Bot API 7.8+)

### User Data & Auth
```js
tg.initDataUnsafe.user        // { id, first_name, username, photo_url, is_premium }
tg.initDataUnsafe.start_param // deeplink param from ?startapp=
tg.initData                   // raw string — validate this on backend with bot token HMAC
```
- Never trust `initDataUnsafe` on backend — always validate `initData` HMAC
- `photo_url` now available to all mini apps (Bot API 8.0+)

### Theme Integration
```js
tg.themeParams.bg_color           // set --bg CSS var
tg.themeParams.text_color
tg.themeParams.hint_color
tg.themeParams.link_color
tg.themeParams.button_color
tg.themeParams.button_text_color
tg.themeParams.secondary_bg_color
// Listen for changes:
tg.onEvent('themeChanged', () => { /* re-apply */ })
```

### Events Worth Listening To
```js
tg.onEvent('activated', fn)          // app came to foreground
tg.onEvent('deactivated', fn)        // app went to background — pause polls
tg.onEvent('viewportChanged', fn)    // keyboard shown/hidden
tg.onEvent('safeAreaChanged', fn)    // orientation change etc
tg.onEvent('backButtonClicked', fn)  // handle back nav ourselves
```

### Haptic Feedback — Use Liberally
```js
tg.HapticFeedback.impactOccurred('light'|'medium'|'heavy'|'rigid'|'soft')
tg.HapticFeedback.notificationOccurred('success'|'warning'|'error')
tg.HapticFeedback.selectionChanged()  // for tab/pill switching
```

### Deployment — Recommended Stack
- **Cloudflare Pages** (not GitHub Pages) — custom headers, instant propagation, CDN
- **Cloudflare Workers** — RPC proxy, CORS headers, environment variables
- Set `Cache-Control: no-store` on `index.html` via `_headers` file in Cloudflare Pages
- Vite content-hash filenames for all JS/CSS assets (already done)
- CI/CD: push to GitHub → auto-deploy to Cloudflare Pages

### Cloudflare Pages `_headers` file (put in /public/)
```
/index.html
  Cache-Control: no-store, must-revalidate
  Pragma: no-cache

/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

### Architecture Lessons
- Lazy-import tab modules (code splitting) — reduces initial bundle
- `stopBlockPulse()` on every tab switch — prevents stale intervals
- Use `tg.onEvent('deactivated')` to pause any live polling (save battery/API calls)
- Use `tg.onEvent('activated')` to resume polls when app comes back
- Bottom nav needs `padding-bottom: env(safe-area-inset-bottom)` on iPhone

## JoyID Auth — Final Working Flow (2026-03-09 ~2pm)

### Root Cause History
- `AUTH_TOKENS` (in-memory Map) removed when KV was added, but stale references remained → crash before KV write
- Fixed: removed all `AUTH_TOKENS.set/delete/iterate` references; KV is the only store
- Double-encoding: `_data_` param arrived as `?data={json}` (JoyID appends its own query prefix) — handled by unwrapping `?data=` prefix before JSON.parse
- Worker success page had garbled emoji (âœ…, â€¦): missing `charset=utf-8` in Content-Type + HTML in template literals contained raw UTF-8 → fixed with `text/html; charset=utf-8` + HTML entities (`&#x2705;`, `&#x2026;`)
- BTC RPC password `nervos123` was hardcoded as fallback in public repo source → removed, now throws if not set via Worker secret

### Working Flow (as of commit `e618f82`)
1. Tap Connect → mini app opens JoyID in browser → calls `tg.close()` on itself after 600ms (prevents stale background instance)
2. Auth in JoyID → Worker `/joyid-callback` parses address → writes to KV (5min TTL)
3. Worker redirects to `https://t.me/WyltekIndustriesBot?startapp=jauth_<base64url-address>`
4. Telegram intercepts link → opens bot → mini app loads fresh with `start_param = jauth_<encoded>`
5. Mini app reads `tg.initDataUnsafe.start_param` at boot → decodes address → stores in localStorage → shows as connected

### Key Insights
- `t.me/BotName?startapp=value` (no `/shortname`) works for any bot with a menu button — no BotFather `/newapp` shortname needed
- KV is globally consistent across all Cloudflare Worker isolates; in-memory Map is NOT (different requests can hit different isolates)
- `tg.close()` on the first mini app instance means only the startapp-opened instance exists — no ghost tab behind
- Telegram mini app shortnames (for `t.me/Bot/shortname`) require `/newapp` in BotFather + title/description/photo — separate from menu button mini app

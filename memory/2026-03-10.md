### CKB On-Chain Auth Pathway
- Fully decentralized alternative to Worker transport
- Device session ID → keccak256 as lock script args → only device can find cell
- Callback page (static/IPFS) writes credential as CKB cell output data
- Device polls CKB Indexer for cell, consumes it (reclaims CKB), net cost ~0.001 CKB
- Possible with Pi5's own CKB light client (192.168.68.91:9001) — zero external deps
- "CKB cells as ephemeral message channels" — uniquely possible on CKB, not ETH/EVM
- Documented in WyAuth/docs/ckb-backend.md

### Two Distinct QR Flows (important distinction)
1. Payment QR: `nervos:<address>?amount=<value>` — opens JoyID wallet, pre-fills tx
   - No callback needed, JoyID handles natively
   - What Blackbox POS uses today
2. Auth QR: `app.joyid.dev/auth?type=redirect&_data_=<encoded>` — proves identity/ownership
   - Needs callback receiver (Worker, CKB cell, Nostr)
   - What WyAuth implements
   - WyVault will use BOTH: payment QR for receiving CKB, auth QR for proving ownership

### OPi3B DSI Backlight — Root Cause Found
- Working overlay: `rk35xx-opi3b-waveshare5-dsi1` (Armbian current/6.18 mainline)
- Uses `panel-dsi-simple` — sends DSI signal, kernel sees `card1-DSI-1: connected`
- BUT: `panel-dsi-simple` has zero backlight support — never talks to Atmel MCU at i2c 0x45
- Atmel MCU confirmed present at i2c-1 0x45 (i2cget returns 0x01)
- `panel-raspberrypi-touchscreen.ko` module exists in 6.18 kernel — but it's a DSI panel driver, not a standalone I2C backlight driver
- Cannot bolt it on top of `panel-dsi-simple` — needs to BE the panel driver
- Dependency cycle in dmesg: `/dsi@fe070000: Fixed dependency cycle(s) with /dsi@fe070000/panel@0` — 6.18 mainline upstream issue
- When we switched to `raspberrypi,7inch-touchscreen-panel` compatible: DSI disappeared entirely (`card1-DSI-1` gone from DRM)

### ckbnode vs OPi3B Kernel Difference — THE KEY INSIGHT
- **ckbnode**: Orange Pi official image, LEGACY branch, **5.10 BSP kernel** (rockchip-rk356x)
  - `/boot/armbianEnv.txt`: `overlays=raspi-7inch-touchscreen`, `overlay_prefix=rk356x`
  - Works because: 5.10 BSP base DTB has pre-defined symbols: `raspits_panel`, `raspits_touch_ft5426`, `dsi1_in_vp0` etc.
  - Overlay just sets `status = "okay"` on pre-existing nodes — trivial!
- **OPi3B (ours)**: Armbian CSC, CURRENT branch, **6.18 mainline kernel** (rk35xx)
  - No pre-defined panel symbols in base DTB — overlay must define everything from scratch
  - DSI graph wiring is complex, dependency cycles kill `raspberrypi,7inch-touchscreen-panel`

### Fix: Switch OPi3B to Armbian Legacy (5.10 BSP)
- Same approach as ckbnode — use `rk356x-raspi-7inch-touchscreen` overlay
- Need Armbian legacy OPi3B image (branch=legacy, not current)
- Alternative: stay on 6.18 and write a full self-contained overlay avoiding dependency cycle (much harder)
- **Recommendation: legacy kernel — it's the proven path that works on ckbnode**

## OPi3B DSI — Live Debug Session (22:00–23:00 ACST)

### Major findings tonight:

**1. STM32 has a ~20 minute self-enable timeout**
- After boot, STM32 at 0x45 does NOT respond to I2C for ~20 minutes
- At ~20 min uptime, backlight came on autonomously — STM32 enabled itself
- After self-enable: REG_ID (0x80) = 0xC3, REG_PORTC (0x82) = 0x85 — Atmel-compatible registers confirmed working
- Before self-enable: all reads return 0x01 (bus noise / no ACK)

**2. DSI signal is reaching the CPLD (backlight on, white screen)**
- When DSI host is active and STM32 self-enables: screen shows WHITE
- White = CPLD (Lattice LCMXO2) is powered and outputting, but not initialised for video
- modetest confirmed DRM CRTC 52 → DSI connector 57 is active, 800x480 mode set
- GDM/Gnome was using its own DRM framebuffer (fb=62, pitch=3200) — /dev/fb0 writes do NOT affect DSI display directly

**3. The CPLD needs TC358762-style bridge init over DSI**
- panel-dsi-simple does NOT send any init commands — just starts DSI clock and declares mode
- The Lattice LCMXO2 needs the same register init sequence as TC358762 (per Raspberry Pi driver)
- Init must be sent as DSI generic writes (6-byte packets: reg_lo, reg_hi, val × 4 bytes)
- The STM32 can proxy these writes via REG_WR_ADDRL/H + REG_WRITEH/L registers

**4. panel-raspberrypi-touchscreen.ko is loaded but can't probe**
- Module exists in 6.18 kernel, loaded successfully with modprobe
- Can't bind because: no DT node with compatible="raspberrypi,7inch-touchscreen-panel" on I2C bus
- Tried runtime new_device — worked to create 1-0045, but DSI device still bound to panel-dsi-simple

**5. The right fix: proper DTS overlay**
- overlay must declare `raspits-panel@45` as I2C child with DSI endpoint graph
- avoid `vp1_dsi_out` as external fixup (this broke v4)
- OR: switch to Armbian legacy 5.10 BSP — ckbnode proves this works

**6. OPi3B crashed** when rpi_panel_init.c tried indirect I2C bridge writes — board required power cycle
